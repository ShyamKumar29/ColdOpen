- Milestone 5 — Camera & Lighting Foundation:
  - Camera Engine (`engines/camera/cameraEngine.ts`, previously a 100%-stub `applyMove` no-op) implemented: owns `x`/`y`/`zoom` `MotionValue`s directly (ADR-017's ownership pattern) and interpolates them via an explicit `tick(now)` step, the same shape and reasoning as the Milestone 3 Animation Engine (ADR-020) — progress is a pure function of the timestamp given, so the engine unit-tests in plain Node with synthetic timestamps (`cameraEngine.test.ts`, 6 tests). `applyMove` is idempotent: re-applying an identical `camera:move` cue is a no-op (CLAUDE.md Event Bus Rules).
  - Camera framing vocabulary (`CameraShot`: `wide`/`medium`/`close`/`twoShot`/`overShoulder`/`reveal`; `CameraFocus`: `left`/`center`/`right`/`wide`) added as bus-owned derived types (`engines/bus/types.ts`), never schema data — the same pattern `CharacterPose` established in Milestone 3 (ADR-019), formalized this milestone as ADR-024. Art-directed in a new `design/camera.ts`: shot→zoom/y, focus→x-bias, move→duration/easing tokens (plus a `prefers-reduced-motion` variant collapsing every move to a nearly-instant cut), and an intensity→magnitude multiplier.
  - Timeline Compiler (`engines/timeline/compiler.ts`) gained `cameraForBeat()`/`autoFraming()`: a pure "virtual cinematographer" that derives a complete `camera:move` cue for every beat from beat type, active speaker, cast size, and the speaker's resolved stage side — explainable from scene state alone, so a script with zero authored `beat.camera` still gets a fully directed path, and an authored direction fills in only what it doesn't specify (ADR-024). A reveal beat's shot is always `'reveal'` regardless of its authored `move`, so the seed script's `whipPan` reveal reads as the dramatic tight framing it's meant to, not a generic wide shot. `resolveInitialSlots()` extracted from `engines/character/characterEngine.ts` as a standalone pure function so the compiler can resolve "which side of the stage is this character on" without duplicating the slot-assignment algorithm.
  - `CameraFrame` (`features/stage/components/CameraFrame.tsx`, new): the single composited-transform wrapper named in `docs/ARCHITECTURE.md`'s component hierarchy (ADR-013) but never built until now. `Stage.tsx` now mounts `Backdrop`/`StageFloor`/`ActorLayer`/`LightingRig` inside it — every in-scene layer moves together on one `transform`; non-diegetic chrome (heading, grain/vignette, subtitles, letterbox) stays outside.
  - `LightingRig` extended (not redesigned, per CLAUDE.md) to crossfade between presets via `AnimatePresence`+opacity instead of swapping instantly, honoring the schema's `transition` (`cut`/`fade`/`flicker`) and optional `durationMs`, reduced-motion-aware (`design/lighting.ts` gained `lightingTransitionTokens`/`reducedLightingTransitionTokens`). Found and fixed a pre-existing Milestone 1 bug this exposed: the rig's `mixBlendMode: 'screen'` compositing makes a black overlay a no-op (`screen(base, black) === base`), so the `blackout` preset never actually darkened the stage — `blackout` alone now renders as an opaque, normally-blended layer so blackout transitions and cut-to-black (the reveal beat's `{preset: 'blackout', transition: 'cut'}`) actually read as black; every other preset's existing screen-blended look is untouched.
  - Found and fixed a root-cause geometry bug this milestone's camera work exposed: `Actor.tsx` applied a character's build-driven height (`silhouetteTokens[...].scaleY`) as a whole-figure `scale()` from a bottom-center origin, which stretched the distance from floor to head-top by the same factor as everything else — a `tall` build's head sat disproportionately higher (and rendered larger) rather than just having longer legs. `Silhouette.tsx` now takes an explicit `heightScale` and applies it as leg-length translation only (foot fixed at the floor, hip raised, torso/arms/head group rigidly translated by the same offset) — every build shares the same head size and neutral head-to-hip proportion; a taller build reads as taller through its legs, not through uniform enlargement. Fixed at this layer deliberately: the Camera Engine and Timeline Compiler were left untouched, since the camera should never compensate for an individual actor's silhouette geometry (ADR-024's decoupling applies here too). See ADR-026. `design/spacing.ts`'s `actorHeightFraction` comment updated to note it's now an intentionally conservative safe upper bound (raw `scaleY`, not the smaller actual leg-only height increase), not a code change. The hip-translation math (`computeRaisedHipY`) lives in its own `silhouetteGeometry.ts` module rather than inline in the component, so it's unit-testable with no rendering — `silhouetteGeometry.test.ts` (new) guards it, including a direct comparison against what the old whole-figure-scale formula would have done, so that regression can't silently return.
  - Bus taxonomy: `camera:move` payload changed from the Milestone 0 stub shape (`{move, target}`) to the fully-resolved `{move, shot, focus, intensity, durationMs?}` — the Camera Engine never looks up a character or beat itself. `light:change` gained an optional `durationMs`. `LightingTransition` moved from an ad hoc local type in `engines/bus/types.ts` into `@schema` (`z.infer<typeof lightingTransitionSchema>`), reused rather than duplicated. `schema/types.ts` gained `CameraMove`/`CameraIntensity` exports (previously only inferred inline).
  - `presentationSlice` gained `currentLightingTransition`/`currentLightingDurationMs` alongside `currentLighting` (defaults to `'cut'` so the very first frame never unwantedly fades in from black); `setCurrentLighting` takes the transition/duration now too.
  - `useSceneController.ts` constructs the Camera Engine alongside the Animation Engine (same lazy-`useState`-once pattern), subscribes `camera:move` to `camera.applyMove(cue, reducedMotion)` in its existing bus-subscribing effect (never inside the engine's own factory — ADR-022's StrictMode-double-invoke lesson applies identically here), and drives `camera.tick()` off the same shared `requestAnimationFrame` loop as `animations.tick()`. Returns `camera` from the bridge; `StageScreen`/`Stage` thread it through as a prop.
  - Rescoped out of this milestone despite `docs/ROADMAP.md`'s prior wording (ADR-025): `beat.movements` (stage-slot movement) and `dialogueBeat.gesture` remain unwired. `ROADMAP.md`'s Milestone 5 entry corrected to describe what actually shipped.

- Milestone 4 — Speech Engine (Clock Handoff):
  - Speech Adapter (`engines/speech/webSpeechAdapter.ts`, new): the only file that touches `window.speechSynthesis`/`SpeechSynthesisUtterance` directly. Implements the provider-agnostic `SpeechAdapter` interface (`engines/speech/types.ts`) — `isSupported`/`loadVoices`/`speak`/`cancel` — so a future cloud-TTS or AI-voice provider is a second adapter file, not a Speech Engine rewrite. Handles the two documented Web Speech quirks: awaits `voiceschanged` with a 1.5s timeout when `getVoices()` returns empty on first call, and holds a hard reference to every live utterance until it settles (the Chromium GC-mid-speech bug).
  - Speech Engine (`engines/speech/speechEngine.ts`, previously an empty stub) is the real implementation of the "Dialogue Engine" responsibilities named in this milestone's brief (queueing utterances, starting/stopping/cancelling speech, exposing speech state) — implemented in the already-scaffolded `engines/speech` folder rather than a new one, since `docs/ARCHITECTURE.md` section 4 already assigns exactly this responsibility set to the Speech Engine; `engines/dialogue` (planning: who speaks, gesture mapping) was left untouched, not needed this milestone. Reacts to `speech:request` cues from the compiled timeline (observation, not a direct call — CLAUDE.md Event Bus Rules) and emits `speech:start`/`speech:boundary`/`speech:end`/`speech:error`/`speech:unavailable`. Splits a line into sentence-sized chunks (`engines/speech/sentenceSplit.ts`, capped at 8) and speaks them as a queue. Every chunk is backed by a watchdog timer at `estimate × 2` (`engines/speech/speechEngine.ts`) that forces the chunk to settle if `onend` never fires, per the documented Speech API risk table.
  - Voice casting (`engines/speech/voiceCasting.ts`, pure function): maps each cast member's schema `voice.register`/`voice.rate` to a pitch/rate pair and deterministically assigns a distinct system voice (preferring `en*` voices) by cast index, so two characters are audibly distinguishable even when the browser exposes only one system voice.
  - `speech:request { characterId, line }` added to `ColdOpenEventMap` (`engines/bus/types.ts`) and to the Timeline Compiler's `CueKind`/`cuesForBeat` (`engines/timeline/types.ts`, `compiler.ts`) — the exact event `docs/ARCHITECTURE.md`'s own section 8 sequence diagram already showed but the bus taxonomy hadn't caught up to. Fires immediately after `subtitle:show` in a dialogue beat's entry cues, in the same synchronous emission loop, which is what keeps the subtitle showing at-or-before speech start without any new subtitle-side code. `CompiledBeat` gained an optional `speechCharacterId`, set only for dialogue beats.
  - Scene Controller clock handoff (`engines/controller/sceneController.ts`): `createSceneController(bus, speech?)` takes an optional, minimal `SpeechClockAdapter` (`{ probeCapability, cancel }`, declared locally in `engines/controller/types.ts` — no import from `engines/speech`, keeping the two engines decoupled per CLAUDE.md). Clock source is decided once per `play()` call. When it's `'speech'`, a dialogue beat no longer completes on its estimated timer duration — it waits for `speech:end`/`speech:error` for its specific speaker (ADR-005), backed by a controller-level watchdog (`durationMs × 2`) in case the Speech Engine's own watchdog somehow doesn't fire. Every non-dialogue beat, and every beat when speech is unavailable, is unaffected and still timer-driven exactly as Milestone 2 left it. See ADR-021 for the resume-from-pause and mid-scene-fallback trade-offs.
  - `hooks/useSceneController.ts` constructs the Speech Engine alongside the bus/controller/animations (same lazy-`useState`-once pattern), passes it into `createSceneController`, calls `speech.castVoices(script.cast)` when a script loads, and syncs `controller.getClockSource()` into the store on every phase transition and on `speech:unavailable`. `playbackSlice` gained `setClockSource` (the `clockSource` field existed since Milestone 2 but had no setter — it was permanently stuck at `'timer'`).
  - Accessibility/degradation: speech unavailability never blocks playback — `SpeechEngine.speak()` immediately emits `speech:error` when the adapter reports unsupported (so the controller doesn't wait out a full watchdog cycle on the very first dialogue beat), and `speech:unavailable` is reported once and causes the controller to fall back to the timer clock for the rest of the scene, arming a timer immediately if a beat was already waiting on speech. Subtitles were not modified — they already render from `currentSubtitle` regardless of whether speech is playing, so "sound off" and "speech unsupported" already degrade to Milestone 2 behavior with no code change needed there.
  - Not implemented, explicitly out of scope per the brief: lip sync/phoneme animation/mouth flap driven by `speech:boundary` (the event is emitted and available for a future milestone, but nothing consumes it yet), AI-generated voices, and any gesture/movement cues (still Milestone 5 scope per the Roadmap).
  - Verified: `format:check`, `lint`, `typecheck` (`tsc -b`), `test` (80 tests — new speech engine/sentence-split/voice-casting suites plus controller and compiler additions for the clock handoff), and `build` all pass with zero errors. Ran the app in a real browser: Play advances through the whole `heist-library` scene noticeably faster than the old fixed timer durations (confirming the speech clock is driving it, not the estimate), subtitles stay in sync with each dialogue beat, Restart/Pause/Resume all produce the correct phase and re-display state without duplicated entrance animations, zero console errors throughout.
  - Post-review cleanup pass: fixed a desync bug the review found — when the Scene Controller's own speech watchdog (not the Speech Engine's per-chunk one) force-advanced a dialogue beat because `speech:end`/`speech:error` never arrived, it left the abandoned utterance running instead of cancelling it, so stale speech could bleed audibly into the next beat. `completeCurrentBeatAndAdvance()` now calls `speech?.cancel()` whenever it's reached with `awaitingSpeechFor` still set (i.e., a forced watchdog advance, not a genuine `notifySpeechEnd`/`notifySpeechError` settlement — `onSpeechSettled` now clears `awaitingSpeechFor` itself before calling it), mirroring the cancellation `pause`/`stop`/`seek`/`restart` already performed. Added a regression test (`sceneController.test.ts`, "cancels stale speech when the watchdog force-advances a dialogue beat...") asserting `cancel()` fires exactly once on the forced path and that a late `notifySpeechEnd` for the abandoned beat's speaker no longer advances playback again. Also documented (comment only, no behavior change) that `speech.castVoices()` in `useSceneController.ts` is fire-and-forget and async, so a `play()` that fires before it resolves gracefully falls back to default pitch/rate/voice for the first line(s). `ROADMAP.md`'s Milestone 4 entry corrected: `onboundary`-driven subtitle reveal/mouth flap and the debug cue log were marked "Complete" despite not shipping this milestone — both are now explicitly listed as deferred, matching what this file already said. Test count corrected from a stale "94" to the actual 80. Re-verified `format:check`/`lint`/`test` (81 tests, +1 for the regression test)/`build` all pass with zero errors.
